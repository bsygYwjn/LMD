# 视频扫描与按需字幕实施记录

日期：2026-09-27。本文区分实现、隔离功能测试、真实素材测量与尚未测量的项目。

## 实现与协议

- 视频扫描用流式目录发现和有界文件检查建立基础索引，首条立即发布，其后独立计时合并。扫描不启动 FFprobe、完整字幕、字体或封面提取。未知编码仍是待探测状态。
- 异步扫描接口立即返回 202 与任务身份，普通/急速共用取消。旧同步接口保留响应结构，并明确 `protocolVersion: 2`、`completion: indexed`。取消保留已经发布的有效条目，未发布缓冲不能在取消后补发。
- canonical 文件身份与库归属分开；重叠库在发布前确定归属。源版本使用 `size:modifiedAt`，派生缓存文件名另用兼容哈希签名。离线、枚举截断和失败不会批量删除旧索引。
- 上传提交只标记关联范围；监听事件合并为脏目录，并以 generation 防止扫描中晚到事件丢失。低频全量校验补偿监听漏报。暂停是全媒体自动扫描开关，重启后保持，不暂停用户实际播放请求。
- catalog/overview 读取已有目录快照，不等待递归刷新。目录库存独立后台更新，缓存不替代上传落盘时的路径与权限检查。
- 全局共享媒体队列支持同源同任务单飞、优先级提升、老化、排队截止、容量上限和独立消费者取消。最后消费者退出才停止底层执行，真实工具退出前仍占并发额度。探测、封面、字幕、字体、位图窗口及显式兼容副本共用预算。
- 未获得可靠物理设备映射时，所有本地盘符保守合并为同一设备组；同 NAS 主机的共享根同组。默认全局 4、设备 2、长读取 1；播放读取占用保护通道并压低后台接纳。播放会话本身仍遵循既有最大流数，这不是硬件吞吐保证。
- `/api/media/:id/info` 按需探测并登记轨道和附件。会话 PATCH 通过 `subtitleTrackId` 与 `subtitleSelectionGeneration` 选择字幕，GET 会话查询独立准备状态。音视频建流不等待完整字幕/字体；关闭、无选中轨道和仅浏览详情不提取。ASS/SSA 才准备当前视频所需字体回退集合，普通文本不提取附件，位图仍走原窗口渲染协议。
- 客户端与服务端共同校验会话、源版本、选择代次；切轨、关闭、离开与重选不会接纳迟到结果。准备失败有重试，字幕按当前播放时间及既有偏移接入。
- 字体内容用原始字节 SHA-256 寻址，来源绑定保留媒体/源/附件/名称/别名。原子发布、持久化屏障、待提交 pin、播放 pin、引用重建和保留期 GC 分开处理。字体 URL 始终先校验媒体权限，不提供裸内容哈希下载接口。
- 旧生成字体仅在实际需要且旧缓存签名/尺寸/格式通过验证时导入；绑定保存后才移除旧生成副本，并保存迁移回执。原始字体和媒体不移动。故障测试全部使用临时目录，真实用户数据未进行迁移。

## 测量与架构取舍

### 真实 HDD 单文件索引对照

使用 D 盘现有 1,597,543,531 字节 MP4，旧代码由任务开始时保存的源代码基线复原。每版 3 次，独立状态和派生缓存，原件只读；操作系统缓存没有清空。首个可见时间是轮询 API 返回，不能代替浏览器首屏或真实首帧。

| 指标 | 原实现 | 新实现 |
|---|---:|---:|
| 冷派生缓存首个 API 条目可见 | 717.9–779.5 ms | 22.9–80.9 ms |
| 冷派生缓存索引流程完成 | 746.7–807.7 ms | 50.8–93.3 ms |
| 开始受理 | 6.1–8.3 ms | 5.7–6.4 ms |
| 首次播放信息请求 | 4.7–11.4 ms（扫描已探测） | 47.6–56.2 ms（按需探测） |
| 索引阶段生成的完整字幕/字体 | 0/0（该样本没有） | 0/0 |
| 索引阶段封面文件 | 1 | 0（可见请求按需） |

这说明该样本的索引发布等待减少，并有约几十毫秒探测工作转移到首次播放请求。没有据此推算 683 部视频的整库倍数，也没有把该请求耗时称作首帧耗时。冷扫描无工具调用另由隔离集成测试检查队列与资源计数。

### 真实多字幕、多字体样本

两集完整 MKV 分别约 2.10 GB、2.59 GB，每集 10 条 ASS、233 个字体附件。仅各选 1 条字幕；未选 18 条保持未准备。输出全部位于独立临时缓存，未截短字幕、未修改字体字节。测试不包含字体别名解析器和浏览器渲染时间。

| 指标 | 第一集 | 第二集 |
|---|---:|---:|
| 首次所选字幕及字体准备 | 4.41 s | 14.10 s |
| FFmpeg 完整字幕提取 | 0.75 s | 12.99 s |
| FFmpeg 字体附件提取 | 0.56 s | 0.60 s |
| 再次选择已准备轨道 | 0.28 s | 0.02 s |

两集产生 466 个来源绑定、233 个唯一内容对象。逻辑字体 308,402,184 字节，唯一字体 154,201,092 字节，**该组样本内容去重率为 50%**；字体目录连同元数据实际为 154,226,722 字节，两条字幕及字体缓存合计 157,286,227 字节。此处的 50% 只对应这两集，不能推广到整库，也不等于先前清理统计中的字体占比 90.2%。首次跨片遇到相同字体仍需提取后才能确认相同字节。

真实样本暴露并修复了 Windows 长命令行问题：233 附件的绝对输出路径超过进程参数限制；现改为专用临时工作目录内的短相对文件名。

### JSON、轮询与大目录

用一个已探测真实记录的结构复制元数据，10 次 compact JSON 序列化测量：683 条约 1.30 MB，中位 4.43 ms；1,000 条约 1.91 MB，中位 6.10 ms；10,000 条约 19.12 MB，中位 64.77 ms、最大 74.19 ms。这是序列化基准，不含磁盘写入、网络或渲染。保留现有 JSON 原子保存/写入合并并增加真实计时；当前约 683 条目标没有引入数据库的前置必要，万级单次同步序列化仍存在约 74 ms 的已知成本。

首期使用有界轻量状态轮询、修订变化才读取列表，避免引入 SSE 连接恢复协议。全量快照按当前权限重取，不依赖不透明公共事件游标。

真实 Chromium DOM 基准（纯元数据，每档 3 次）发现万级全量卡片渲染为 150,110 个节点，首屏 2.33–2.72 s、搜索 857–950 ms、长任务 290–320 ms；千级首屏 267–280 ms、搜索 70–101 ms。因此采用每页 120 项可访问分页，保留搜索、选择、播放、键盘导航和页码，避免一次挂载全部卡片。最终万级复测首屏 110–151 ms、搜索 34–42 ms、1,918–1,924 个 DOM 节点，未记录到超过 50 ms 的长任务。该结果不代表磁盘扫描或视频首帧性能。

### 真实播放器浏览器验收

隔离服务使用生成的 60 秒 H.264/AAC MKV、默认 ASS、第二条 SRT 及原始 Arial 字体附件。字幕响应人为延后 1.8 秒时，浏览器约 762 ms 开始播放，证明音视频启动没有等待字幕响应；这不作为 HDD 吞吐基准。已视觉核验 ASS 实际绘制，并验证 A→B→关闭拒绝迟到结果、失败显式重试、seek 保留偏移且不重提取，以及退出释放会话。

真实渲染发现 JASSUB 2.4.1 的动态 JS 调用器与现有严格 CSP 冲突。构建时只替换已核对版本的调用器为等价闭包，不放宽 CSP；单测在禁止字符串代码执行的 VM 中覆盖参数、this、返回值及析构行为，依赖实现变化时构建会明确失败。

## 升级与回滚

- 当前工作区原有上传、下载、其他文件及设置组件修改。此次基础扫描依赖上传发布钩子、隐藏暂存路径、目录库存和对应权限模块；提交前按文件及依赖审查，保留运行所需模块。与本任务无关的既有文档和界面改动单独保留。
- 原始工作区差异、未跟踪代码副本、原始 HEAD 和测量输出保存在忽略的 `data/development-baselines/video-scan-20260927`，不进入 Git。
- 升级前备份实际状态与程序。源码/构建更新不覆盖用户配置、访问凭证、播放历史或原始媒体。运行实例端口为 8096，自动扫描暂停状态必须保持。
- 回滚先停止服务及任务，恢复备份的程序和兼容状态。若测试之外未来发生旧字体迁移，可用 `fonts/migration-log` 回执和共享对象恢复旧生成文件，再恢复兼容绑定；不可仅替换旧 JS 后继续使用已移除的旧路径。不要对原媒体目录执行恢复性删除。
