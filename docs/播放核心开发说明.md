# LMD 播放核心开发说明

本文说明统一媒体播放核心的结构、处理规则与各项配置的来源。产品边界与验收标准以项目文档为准，这里只描述已经实现的代码。

## 1. 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 元数据与策略 | `server/playback-planner.mjs` | 版本化媒体元数据、逐轨选择、四种策略、配置校验 |
| fMP4 解析 | `server/playback-mp4.mjs` | 增量读取 ISO BMFF box、分片时间、初始化段时长写入 |
| 播放服务 | `server/playback.mjs` | 媒体信息、播放会话、原文件 Range、FFmpeg 分片、HLS 清单、Seek、共享、租约、缓存回收 |
| 位图字幕 | `server/bitmap-subtitles.mjs` | PGS/VobSub/DVB 图片解码与按需切片 |
| 弹幕服务 | `server/danmaku.mjs` | 弹弹play 匹配、聚合弹幕、本机绑定 |
| 真实浏览器自检 | `server/player-test.mjs` + `src/player/player-test.tsx` | 在真实浏览器中驱动界面并回传报告 |
| 前端核心 | `src/player/core.ts` | 能力检测、Direct/HLS 适配、原片时钟、Seek、自动后备、心跳与释放 |
| 前端界面 | `src/player/Player.tsx`、`player.css` | 播放舞台、控制条、快捷键、移动手势、锁定与全屏 |
| 字幕与弹幕 | `src/player/subtitles.tsx`、`danmaku.tsx`、`danmaku-time.ts` | ASS/文本/位图字幕渲染，弹幕渲染与三层时间映射 |
| 系统媒体控制 | `src/media-session.ts` | 视频与音乐共享一套 Media Session 所有权 |

上层模块只通过 `PlaybackCore` 的接口与状态工作，不重复实现按策略分支的控制逻辑。

## 2. 播放策略

策略由 FFprobe 轨道信息与浏览器上报的能力共同决定，扩展名不参与判断。

| 策略 | 条件 | 视频 | 音频 |
|---|---|---|---|
| DIRECT | 容器与所选轨道原生可放 | 原样直传（Range） | 原样直传 |
| REMUX | 编码兼容，仅容器或轨道选择需要调整 | Copy | Copy |
| PARTIAL_TRANSCODE | 只有部分所选轨道需要编码 | Copy | Encode |
| TRANSCODE | 所选音视频都需要转换；无音轨时只看视频 | Encode | 需要时 Encode |

关键规则：

- MKV/H.264/AAC 在客户端支持这两个编码时必须双 Copy。
- 不兼容音频（例如 DTS）只转换音频，视频保持 Copy。
- HEVC/AV1/VP9 只要设备能解就保留原编码。
- Copy 路径不降分辨率、不改位深、不混成立体声。
- 转码默认输出 H.264；音频只在必要时转 AAC，多声道在设备支持时保留 6 声道。
- HDR 在必须转码时执行 HDR→SDR 映射。
- 硬件编码器（`h264_nvenc`/`h264_qsv`/`h264_amf`）先做运行时探测，失败回退 `libx264`。

策略结果带有 `reason` 与逐轨 `action`，用于诊断和测试；控制界面不暴露 FFmpeg 参数。

## 3. 传输与时间轴

- DIRECT 使用原文件 Range 接口（`200/206/416/HEAD`、`Content-Range`、`Accept-Ranges`），不启动 FFmpeg。
- 其余策略由 FFmpeg 按需产出 fMP4 分片：Chrome/Edge/Firefox 走 hls.js + MSE，具备合适 MMS 能力的 iPhone 走 MMS，Safari 保留原生 HLS 后备，三者复用同一份产物。
- HLS 在 FFmpeg 运行期间使用普通滑动清单，不声明 `VOD`；`TARGETDURATION` 在管线创建时固定为 6 秒，FFmpeg 以 4 秒作为最大分片节奏，避免客户端轮询期间目标时长变化。
- 清单只发布已经写完并可读取的分片；`moof` 与 `mdat` 分块写入 `.part`，完整写完后原子改名。处理窗口结束不等于原片结束，因此只有 FFmpeg 正常退出后才追加 `#EXT-X-ENDLIST`。
- fMP4 读取器在读到 box 头后即提供异步分块，不再反复 `Buffer.concat` 大 `mdat`，也不会为 `moof + mdat` 创建第二份完整分片。
- 时间映射按实际时间戳计算：`原片时间 = 当前传输时间 + 会话时间映射`。Copy 路径的偏移取自首帧真实 PTS 与输出分片 PTS 之差，不使用请求的 Seek 时间冒充偏移。
- 初始化段写入原片精确时长，避免浏览器根据已生成分片推测出偏短的时间轴。

Seek 流程：保存播放意图与轨道选择 → 命中缓冲则直接定位 → 未命中则使旧代次失效、取消旧请求 → 在目标附近重建处理窗口 → 取得初始化片与可播放分片 → 恢复时间与播放状态。连续快速 Seek 只接受最后一次结果，旧代次的分片与事件会被拒绝（`409`）。

## 4. 会话与缓存生命周期

- 会话按消费者计数，心跳默认 10 秒、租约 45 秒；同一会话的多个分片请求不重复占用播放名额。
- 相同处理任务共享同一个 FFmpeg 进程与产物；一人 Seek 只释放自己的引用，不终止其他人的播放。
- 停止条件统一收敛在一处：关闭页面、切换媒体、Seek、播放结束、租约到期、无输出超时、服务关闭、缓存被逐出。
- 每个任务结束时都会取消输入输出、关闭管道、解除消费者引用、清理监听器与计时器、移除未完成产物，并按缓存规则保留已完成分片。
- 缓存按 `源文件签名 + 轨道 + 编码参数 + 打包版本` 标识；TTL/LRU 不会删除正在读取或仍受租约保护的分片。
- 服务重启只回收 `data/cache/playback` 内可确认归属的残留，不扫描或删除原始媒体与历史兼容副本。
- 原文件被替换后，会话与管线立即失效并返回 `SOURCE_CHANGED`，前端重新拉取元数据并重建会话。

## 5. 之前修复的具体缺陷

这些是为了让上述规则真正成立而修掉的实现问题，回归测试覆盖其中可自动化的部分：

| 问题 | 影响 | 处理 |
|---|---|---|
| 扫描最终合并时优先取旧对象 | 目录里的 `size`/`modifiedAt` 可能落后于磁盘，播放会话随即被判为 `SOURCE_CHANGED` | 合并时优先使用本次扫描发布的对象，并保留就地刷新 |
| 就地补探元数据后不刷新身份字段 | 同上，且 `playbackMetadata` 与记录签名互相矛盾 | 补探成功后同步写入当前 `size`/`modifiedAt` |
| 客户端释放请求未带 `keepalive` | 页面卸载时 DELETE 被浏览器取消，会话只能等租约到期 | 释放请求改为 `keepalive` |
| `setPointerCapture` 未做保护 | 指针已消失时抛错，中断整次手势 | 捕获失败按普通定位处理 |
| 位图字幕窗口请求不取消旧结果 | 连续 Seek 时旧位置的图片可能被画上去 | 窗口请求带代次校验，旧结果直接丢弃 |
| 初始化段未写时长 | 浏览器只看到已生成分片，时长与进度条偏短 | 初始化段写入原片精确时长 |
| 未知音轨 ID 直接失败 | 换片或重新分析后旧轨道 ID 会让会话创建失败 | 音频轨道 ID 失效时回退默认轨道，视频轨道仍报错 |
| 动态 HLS 错误声明 VOD，目标时长随分片变化 | 原生 HLS 可能停止刷新或错误 Seek | 运行中使用滑动清单，目标时长固定，EOF 后只追加 `ENDLIST` |
| 大 `mdat` 反复拼接并整段复制 | 高码率或并发播放时 CPU、RSS 与首帧延迟放大 | box 分块流式读取，分片直接写临时文件并原子发布 |

## 6. 弹幕时间的三层映射

1. 供应方时间轴：弹弹play 返回的时间已经由对方校准，标记为 `provider`，不得再次叠加。
2. 当前媒体版本保存的映射：整体偏移或分段锚点。
3. 用户本次设置的附加偏移。

规则：

- **正值表示弹幕更晚出现**。整体偏移与分段锚点都遵循同一方向。
- 分段锚点只影响该锚点**之后**的弹幕；锚点之前保持来源时间，避免把用户没有指定的偏移套用到更早的弹幕。
- 删除区间（例如剪掉 OP）用独立区间表示，区间内的弹幕被丢弃而不是平移。
- 同一弹幕在映射之后按“映射时间 + 模式 + 文本”跨来源去重，供应方不同的同一句话只显示一次。
- 单来源上限 100000 条、单次显示上限 120000 条、来源最多 8 个，避免导入文件把内存顶满。
- 没有可靠参考时不按总时长比例拉伸弹幕。

## 7. 已知限制

- 弹弹play 在线联调需要本机配置有效 AppId/AppSecret；当前实现只做了无凭证、限流、多候选与失败路径的验证，**未做有效凭证联调**。
- 位图字幕（PGS/VobSub/DVB）的解码管线以桩件验证了索引、窗口、发布与错误路径；**没有真实位图样片做逐帧比对**。
- ASS 全特效样片、Android、Safari、真实 iPhone/iPad、长 GOP/高码率压力与完整性能矩阵**尚未验收**。
- 主包体积约 1 MB（gzip 约 312 kB），hls.js 仍随主包加载；后续可改为动态加载。
